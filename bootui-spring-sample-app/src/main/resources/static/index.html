Thread investigation lab

      

        Run one scenario at a time, for at most 30 seconds. Open
        Threads to inspect it. No Java agent needed.
      

      

        How to inspect thread scenarios
        

          Capture snapshot opens Contention;
          Observe threads opens Observe & compare. For current states, choose
          Live in Thread source and filter for sample-threads-.
          Snapshots and observations also work with low-footprint mode on.
        

      

      

        
        
        
      

      

      

        

          
          
One owner holds a monitor while three workers are BLOCKED.

          Capture snapshot → Contention: inspect the root blocker and downstream impact.
        

        

          
          
Three workers park behind a ReentrantLock owner.

          Capture snapshot → Contention: follow exclusive waits back to the lock owner.
        

        

          
          
One RUNNABLE worker uses one CPU core for bounded computation.

          Observe threads → Observe & compare: inspect measured interval CPU, not cumulative CPU totals.
        

        

          
          
Three workers wait at the same call site without an exclusive lock dependency.

          Capture snapshot → Contention: inspect stack groups. Observe threads → Observe & compare: see repeated stacks.
        

        

          
          
Two workers each hold a lock the other needs. Stop or automatic expiry releases both safely.

          Capture snapshot → Contention: inspect the native deadlock alert and supported wait cycle.

        Java agent and enable the corresponding sensor. The requests also work without the agent, but produce no
        agent findings.

          Sensor: network. Inspect: Side Effects
